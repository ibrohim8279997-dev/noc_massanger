# Этап 1, модуль «шифрование» (client-android/core-crypto): отчёт

Запуск: `cd client-android && gradle test` (Kotlin/JVM 21, libsignal-client 0.86.5, нативная часть из libsignal-server только для тестов). 20 тестов проходят. Плюс серверный тест `server/tests/test_client_vector.py` проверяет подпись Kotlin-клиента кодом сервера.

## Что сделано
- PQXDH через libsignal: X25519 + ML-KEM-1024 (Kyber1024), Double Ratchet. Своей криптографии нет.
- Доверие только к ключам, закреплённым при личной встрече (QR). Неизвестный собеседник: сессия не создаётся. Смена ключа: отказ, пока пользователь явно не подтвердит.
- Конверт фиксированной длины 16384 байта со случайным заполнением. Отправитель, время, тип и таймер автоудаления лежат внутри шифртекста.
- Файлы и голосовые: случайный ключ на файл, AES-256-GCM по кускам, ключ только внутри зашифрованного манифеста, SHA-256 каждого куска и файла, привязка куска к файлу, номеру и числу кусков (подмена и перестановка отклоняются), докачка недостающих.
- Подпись запросов Ed25519 по `protocol/server-api-v1.md`; совместимость с сервером подтверждена вектором.
- QR-приглашения: срок жизни, одноразовость на стороне выдавшего, строгий разбор. Номер безопасности (60 цифр) одинаков у обоих.

## Проверено тестами
Шифрование туда и обратно, смена ключа на каждое сообщение, повтор отклоняется, одинаковый размер для сообщений 0..11500 байт, случайность заполнения, подделка и неверный размер, файл через настоящие сессии (включая самое большое первое сообщение) с обратным порядком кусков, утерянные и подменённые куски, неверная контрольная сумма, пустой файл, мусорные приглашения.

## Не сделано (нужен Android SDK) и ограничения
- Не написаны и не проверены: хранилище SQLCipher на Android, ключи в Android Keystore, BiometricPrompt, автоблокировка, FLAG_SECURE, проверка root/debug, экраны, QR-сканер, автоудаление в БД. Без SDK их нельзя ни собрать, ни проверить, поэтому код я не писал вслепую.
- Хранилище сессий libsignal сейчас в памяти (`InMemorySignalProtocolStore`). Для приложения нужна версия поверх SQLCipher.
- Тип сообщения libsignal (первое или обычное) различим по структуре шифртекста. Полностью скроет sealed sender в этапе 2.
- Проверки безопасности этапа 1 (минимум пять по ПО и открытому телефону, плюс подмена человека) будут выполнены, когда появится Android-часть. Часть про подмену человека покрыта тестами выше.
- Независимый аудит кода по-прежнему рекомендуется.
