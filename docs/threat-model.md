# Модель угроз

## Что защищаем
Содержимое сообщений и файлов, граф общения, ключи, учётную запись суперадмина, физический сервер.

## Риски и меры

### 1. Телефон открыт или потерян разблокированным
- Автоблокировка приложения по таймеру, повторный вход BiometricPrompt/PIN.
- FLAG_SECURE, скрытие содержимого в списке недавних, запрет записи экрана.
- Автоудаляемые сообщения. Отзыв ключей устройства при потере.

### 2. Вредоносное ПО на устройстве
- Ключи в Android Keystore, БД в SQLCipher.
- Проверка целостности приложения, отказ на root и при включённой отладке.
- Ни ключи, ни токены, ни тексты в логах, буфере обмена и резервных копиях (`allowBackup=false`).

### 3. Ошибки в нашем коде (особенно Tor, mesh, cover traffic)
- Только библиотеки для криптографии, параметризованные SQL, строгая валидация входа.
- Десять проверок с циклом исправления после этапов 2 и 4.
- Рекомендация: независимый аудит кода.

### 4. Уязвимости библиотек, Tor, Android
- Закрепление версий, регулярное обновление, обновление сервера только через Tor.

### 5. Подмена человека
- Сверка отпечатков вручную, одноразовый QR, явное предупреждение при смене ключа.

## Что осознанно вне рамок
- Компрометация самого телефона-сервера физически (диск шифруется, но с доступом к работающему устройству ключ в памяти).
- Анализ трафика глобальным наблюдателем до этапа 2.
- Уязвимости ОС выше уровня приложения.

## Известные риски платформы
- Termux на Android: ограниченные права, нет полноценного nftables без root, фаервол «только Tor» придётся строить иначе (VPN-сервис/Tor transparent proxy). Решение в ADR перед этапом 3.
- Сборка SQLCipher под Termux нетривиальна; проверяется в первом модуле сервера.
