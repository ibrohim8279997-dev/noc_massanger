# ADR-006: ML-DSA для суперадмина

Статус: реализовано по решению владельца (выбран liboqs).

- Суперадмин подписывает каждое действие **двумя подписями**: Ed25519 и ML-DSA-65 (FIPS 204) из liboqs 0.14.0. Сервер требует обе, поэтому взлом одного алгоритма сам по себе не даёт доступа.
- ML-DSA подпись идёт в заголовке `x-pq-sig` и покрывает ту же каноническую строку запроса с префиксом `NOC1-PQ\n` (разделение доменов).
- Привязка и смена ключа регистрируют обе пары ключей; для смены нужно доказательство владения обоими новыми ключами.
- Сервер вызывает liboqs через ctypes, клиент через тонкий JNI-мост (`native/nocoqs/oqs_jni.c`). Криптографии в них нет.
- Источник liboqs закреплён по хешу коммита (`tools/fetch-liboqs.sh`); сборка минимальная, только ML-DSA-65.
- Независимая проверка: BouncyCastle принимает подписи liboqs и наоборот.
- Ключ ML-DSA хранится на телефоне администратора обёрнутым ключом Keystore (как Ed25519), по поколениям: смена ключа не может закрыть доступ.

Остаётся классическим: подписи обычных пользователей и подписи внутри протокола Signal (решение ADR-001).
Не проверено: исполнение arm64-библиотеки на устройстве (проверена статически), производительность на телефоне.
