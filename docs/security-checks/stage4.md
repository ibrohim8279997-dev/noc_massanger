# Этап 4: mesh, проверки

Запуск: `tools/stage4_checks.sh` (десять проверок). Каждая привязана к именованным тестам, скрипт читает результаты из JUnit XML: проверка проходит, только если эти тесты существуют и прошли. Правило цикла: находка, исправление, все десять заново с начала.

## Круги
**Круг 1.** Находки:
1. Отправка падала без сервера: `Messenger.send` сначала писал на сервер, и недоступность сервера обрывала отправку до mesh, то есть ровно в сценарии, ради которого mesh нужен. Исправлено: два независимых пути, ошибка только если не сработал ни один.
2. Конверт не удалялся у отправителя, если сосед уже имел его: сосед отвечал «не нужно» без подтверждения, и копия жила до конца срока. Исправлено: известные соседу сообщения подтверждаются сразу.
3. Тест `only_the_intended_receiver_can_ask_for_chunks` оказался пустышкой (проверял тривиальное). Переписан, проверен **мутацией**: без защиты в коде он падает.
4. Тест «потери были настоящими» был нестабилен (случайные потери иногда не теряли ничего). Первый раунд сделан детерминированным; три прогона подряд зелёные.

**Круг 2.** Все десять заново: пройдены. Регрессия: проверки этапов 2 и 3 по-прежнему проходят.

## По проверкам
| № | Проверка | Результат |
|---|---|---|
| 1 | Все пакеты одной длины | Конверт ровно 4096 байт для любого сообщения; фрагменты по радио до 193 байт |
| 2 | Нет постоянных идентификаторов | Id, одноразовый ключ, подпись, метка, заполнение случайны у каждого сообщения. В рекламе только UUID, меняется каждые 5 минут, нет имени, мощности, данных производителя; характеристика GATT тоже меняется |
| 3 | Ретранслятор не читает | Только шифртекст Signal; в симуляции у ретрансляторов нет собеседников; буфер зашифрован |
| 4 | Каждое сообщение подписано | Подпись одноразовым ключом (целостность) плюс метка круга HMAC (членство); подделка, чужой круг, просрочка, лишние прыжки, порча отклоняются |
| 5 | Буфер ограничен | По числу и байтам, вытесняется то, что истекает раньше; спам от соседа ограничен и обрывается |
| 6 | Файлы кусками с контрольными суммами | AES-GCM и SHA-256 на кусок, SHA-256 файла и конверта, CRC на фрагмент; недостающие куски запрашиваются и досылаются через потери; запрашивать может только получатель |
| 7 | Bluetooth-идентификаторы | Меняются, одинаковы у всего круга, находят друг друга при расхождении часов. **Смена аппаратного адреса делает Android, приложение его не видит и не задаёт** |
| 8 | Ретранслятор удаляет следы | Удаление только после подтверждений соседей (по умолчанию 3) или по сроку, не раньше; после этого в памяти нет метки соседа, получателя, содержимого, остаётся только 64-битный хеш одноразового id в двух поколениях без времён (защита от петель, только RAM) |
| 9 | Шифрование в покое | Файлы буфера: AES-GCM, случайные имена, перезапись нулями при удалении, остатки прошлого запуска уничтожаются; ключ только в оперативной памяти |
| 10 | Сквозная проверка | Доставка через два ретранслятора и цепочку из пяти ровно один раз с настоящими сессиями Signal; сообщение по серверу и по mesh доставляется один раз; 100 сообщений по случайной сети, буферы ограничены; код mesh не открывает сетевых соединений и не пишет логов |

## Не реализовано и не проверено
- **Wi-Fi Direct / Nearby Connections для файлов не сделаны.** Файлы идут по Bluetooth малыми кусками (до 200 КБ), это медленно. Nearby Connections требует сервисов Google Play, это вопрос доверия (спросить).
- **Код Bluetooth (`BleMesh`) написан по API платформы, на устройствах не запускался.** Все проверки выше выполнены на симулированном радио с настоящей логикой.
- Круги из разных цепочек знакомств, не объединённые общим QR, не сливаются (ключи круга разные). Для первого сообщения нужна уже существующая сессия.
- Подпись сообщения relay-уровня анонимна по замыслу (иначе нужен постоянный идентификатор); защита от спама внутри круга опирается на метку круга, лимиты и буфер.

## Дополнение: большие файлы и быстрые каналы (Wi-Fi Direct, Nearby)
Блок расширен до 17 проверок (11 по 17 новые). Результат: все 17 пройдены, 119 тестов.

Находки по пути (все исправлены, проверки запущены заново с начала):
1. **Ошибка этапа 1:** манифест файла нёс суммы всех кусков и рос вместе с файлом. Файл больше ~4,5 МБ не помещался в серверный конверт, по mesh больше 100 КБ. Теперь сумма куска едет вместе с куском, манифест постоянного размера; проверено на файле 20 МБ и на настоящем сервере с файлом 5 МБ.
2. **Возможная взаимная блокировка** узла mesh и мессенджера (доставка вызывалась под блокировкой узла). Доставка теперь вне блокировки; тест гоняет трафик в обе стороны одновременно.
3. Пустой файл отвергался новой проверкой длины куска. Исправлено.
4. Лимит сервера (120 пакетов в минуту на ящик) и размер ящика (1000) не подходили для больших файлов; теперь настраиваются, ящик 2500 пакетов.
5. Старый тест докачки не проверял запрос недостающих кусков (потерянное досылалось само); новые тесты проверяют именно запросы.

Не проверено: все три радио на реальных телефонах. См. ADR-007.
