# ADR-007: большие файлы по mesh, Wi-Fi Direct и Nearby Connections

Статус: реализовано по решению владельца («мессенджер должен быть функциональным»). Радио-код не проверен на устройствах.

## Большие файлы
- Файл идёт кусками по 1700 байт (mesh) или 11000 байт (сервер). Контрольные суммы трёх уровней: GCM-метка куска (привязана к id файла, номеру, числу кусков, размеру), SHA-256 куска (едет вместе с куском), SHA-256 всего файла (в манифесте).
- **Манифест больше не растёт с размером файла** (раньше нёс список сумм всех кусков: файл больше ~4,5 МБ не помещался в серверный конверт, а по mesh больше 100 КБ). Это исправление ошибки этапа 1.
- Передача окнами по 32 куска: отправитель сразу шлёт манифест и первое окно, остальное получатель запрашивает по мере получения (E2E-сообщение FILE_NEED). Буфер ретранслятора остаётся ограниченным (64 конверта, 128 с быстрой связью). Потерянные куски запрашиваются повторно через 30 секунд.
- Предел: 20 МБ. Ящик на сервере вмещает 2500 пакетов (около 41 МБ), чтобы файл ждал офлайн-получателя.

## Быстрые каналы
Общая логика одна для всех трёх радио (`MeshSession`, проверена тестами): сначала взаимное доказательство принадлежности к кругу (запрос-ответ с ключом круга, роли разные, отражение невозможно), потом обмен конвертами. Посторонний, подключившийся по Wi-Fi или Nearby, не получает даже запечатанных конвертов.
- **Bluetooth:** фрагменты до 194 байт, с контрольной суммой на фрагмент и на конверт.
- **Wi-Fi Direct** (платформенный API, без Google): сервис DNS-SD с вращающимся именем из ключа круга, TCP-сокет внутри группы. **Цена для приватности: Wi-Fi Direct показывает имя телефона людям рядом**, приложение не может это скрыть. По умолчанию выключен.
- **Nearby Connections** (сервисы Google Play): идентификатор службы вращающийся, имя конечной точки случайное. **Радио управляет закрытый код Google**, на этом канале вы полагаетесь на Google. Без Play services не запускается. По умолчанию выключен.
- Для API 30–32 Wi-Fi Direct требует разрешение на геолокацию (системное требование); с API 33 используется NEARBY_WIFI_DEVICES с флагом neverForLocation.

## Найдено по пути
- Возможная взаимная блокировка узла mesh и мессенджера (доставка вызывалась под блокировкой узла): исправлено, доставка идёт вне блокировки, проверено тестом с одновременным трафиком в обе стороны.
- Пустой файл отвергался новой проверкой длины куска: исправлено тестом.

## Не проверено
Всё радио (Bluetooth, Wi-Fi Direct, Nearby) на реальных телефонах; пропускная способность и расход батареи. Скорость по Bluetooth низкая: файл 200 КБ это около 120 конвертов.
