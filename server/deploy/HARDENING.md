# Усиление сервера (этап 3)

Порядок на телефоне-сервере (Debian). Всё делается руками на самом телефоне, удалённого входа нет.

1. `bash server/deploy/tor-setup.sh`: onion-сервис, адрес печатается в конце.
2. `bash server/deploy/create-user.sh`: создаёт пользователя `noc`, каталог `/var/lib/noc` (режим 700).
3. Обновления системы только через Tor: `cp server/deploy/apt-tor.conf /etc/apt/apt.conf.d/99tor`.
4. Фаервол: `nft -f server/deploy/firewall.nft` (политика «запретить» в обе стороны, наружу только процесс Tor, без исключений).
5. Запуск: `NOC_RUN_AS=noc NOC_HOST=127.0.0.1 bash server/deploy/linux-run.sh`.
6. Проверка хоста: `bash server/deploy/audit.sh` (слушаются только loopback-порты, нет sshd/tailscaled, каталог данных закрыт).

SSH не устанавливается и не включается, Tailscale не используется.

## Важное ограничение
Фаервол (шаг 4) работает на реальном ядре Linux с netfilter. В proot-окружении внутри Termux без root-прав он, скорее всего, не загрузится. Тогда защиту дают остальные меры: сервер слушает только 127.0.0.1, SSH нет, обновления идут через Tor, а процесс работает от пользователя без прав. Поведение правил проверено в изолированных сетевых пространствах (`tools/firewall_test.sh`), но не на вашем телефоне.

## Потеря устройства администратора
Остановить сервер, на телефоне выполнить `python -m app.cli reset-superadmin` (с теми же `NOC_DB_PATH` и ключом), запустить снова: напечатается новый одноразовый токен. Токен можно получить только так, удалённо его выдать нечем (проверяется тестом).
