# ADR-003: решения по Android-клиенту (этап 1)

Статус: реализовано, ждёт подтверждения владельца там, где отмечено «спросить».

1. **minSdk 30 (Android 11).** Нужен BiometricPrompt с «биометрия или экранный замок» и параметры авторизации ключа Keystore.
2. **Ключ устройства Ed25519: BouncyCastle, не Keystore.** Сервер ждёт обычный Ed25519, а Keystore умеет его только с Android 13. Зерно ключа лежит в SQLCipher (главный ключ БД обёрнут ключом Keystore). Ключ суперадмина отдельный: зерно обёрнуто ключом Keystore, который требует свежей биометрии или PIN (окно 10 с) перед каждым действием. Спросить: нужен ли строгий вариант «ключ устройства только в Keystore» с минимумом Android 13.
3. **Главный ключ БД** обёрнут ключом Keystore с обязательной проверкой экранного замка; без экранного замка приложение не запускается. После блокировки база закрывается.
4. **Этап 1 ходит на сервер напрямую по HTTP/WS** (`usesCleartextTraffic`). Содержимое зашифровано сквозным шифрованием, но сервер видит IP и факт подключения. Закрывается этапом 2 (Tor).
5. **Отправитель скрыт внутри конверта,** поэтому получатель пробует расшифровать пакет ключами каждого контакта. Годится для небольшого круга, масштабируется плохо. Нерасшифровавшийся пакет удаляется с сервера.
6. **Нет фоновой службы и push:** сообщения приходят, пока приложение разблокировано. Фон потребовал бы хранить ключ БД открытым при заблокированном телефоне. Спросить, если нужны уведомления.
7. **Один модуль `app`** вместо `core-storage`, `core-net`, `core-security`: пакеты `data`, `net`, `security` внутри него. Криптография вынесена в отдельный JVM-модуль `core-crypto`, потому что она тестируется без Android.
8. **Релиз подписан локальным debug-ключом.** Для распространения нужен свой ключ. Целостность: при первом запуске запоминается подпись приложения, при несовпадении запуск отказывается.
